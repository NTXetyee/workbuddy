# WorkBuddy SPEC (v1)

iPad mini 6 as a USB second screen for a Windows PC. Latency beats quality everywhere.

## 1. Fixed decisions
- Transport: USB via usbmuxd. The iPad app LISTENS on TCP port **7878**. The host connects through usbmuxd (`127.0.0.1:27015` on Windows, Apple Mobile Device Service) to that device port. No Wi-Fi, no WebRTC.
- Host: Rust (stable, MSVC), Windows 11. Crates under `host/crates/`.
- Capture: DXGI Desktop Duplication on the virtual monitor output. Frames stay on the GPU.
- Convert + encode: D3D11 VideoProcessor (BGRA->NV12, scaling) then a **hardware H.264 Media Foundation transform** (vendor-agnostic: NVENC on the RTX 5060, AMF on the 780M, QuickSync). Low-latency config: no B-frames, no lookahead, tiny VBV, CBR, GOP effectively infinite (IDR only on request or at start), low-latency mode on. Direct NVENC/intra-refresh is a post-M1 optimisation.
- Virtual display: existing open-source IddCx driver (VirtualDrivers/Virtual-Display-Driver). No custom driver. User installs it once (admin).
- iPad: Swift, iOS 16+ target, SwiftUI shell. VTDecompressionSession -> AVSampleBufferDisplayLayer. Built unsigned on GitHub Actions (macos-latest), packaged `.ipa`, sideloaded via AltStore. Project generated by XcodeGen from `ios/project.yml`; never a hand-edited .xcodeproj.
- iPad app is dumb: all tunables (resolution, fps, bitrate) come from the host in a CONFIG message.
- Repo: `NTXetyee/workbuddy`, public.
- Milestone 1 (M1): H.264 host -> iPad display over USB. No input, no Pencil, no rotation, no tray polish.

Non-goals (for now): audio, multiple iPads, HDR, clipboard, Wi-Fi, Pencil, autostart, polished UI, HEVC.

## 2. Wire protocol v1 (Task 0)
All integers **little-endian**. A stream is a sequence of frames: `Header(12 bytes) + payload(len bytes)`.

### 2.1 Header
| Off | Size | Field | Notes |
|---|---|---|---|
| 0 | 1 | magic0 | `0x57` ('W') |
| 1 | 1 | magic1 | `0x42` ('B') |
| 2 | 1 | version | `0x01` |
| 3 | 1 | type | see 2.2 |
| 4 | 4 | seq (u32) | per-direction counter starting at 0, wraps. Diagnostic only. |
| 8 | 4 | len (u32) | payload length, max `4194304` (4 MiB). Larger = protocol error, close. |

Bad magic or version = protocol error: close the connection. Unknown `type` = skip `len` bytes, keep going (surfaced as `Unknown`).

### 2.2 Message types
| Type | Name | Dir | Payload |
|---|---|---|---|
| 0x01 | HELLO | iPad->host | 11 bytes + name (below) |
| 0x02 | CONFIG | host->iPad | 12 bytes |
| 0x03 | VIDEO | host->iPad | 12-byte header + Annex-B data |
| 0x04 | KEYFRAME_REQUEST | iPad->host | empty |
| 0x05 | PING | either | u64 timestamp_us (sender clock) |
| 0x06 | PONG | either | u64 echo of the PING timestamp |
| 0x07 | ORIENTATION | iPad->host | u8 (0=landscape, 1=portrait). Reserved, post-M1. |
| 0x08 | STATS | iPad->host | 12 bytes |
| 0x09 | BYE | either | empty |
| 0x10 | TOUCH | iPad->host | reserved, post-M1 |

**HELLO** (iPad sends first, right after accept):
`proto_version u8 | codecs u8 (bit0=H264, bit1=HEVC) | orientation u8 | reserved u8 (0) | native_width u16 | native_height u16 | max_fps u16 | name_len u8 | name[name_len] (UTF-8)`.
Fixed part = 1+1+1+1+2+2+2+1 = **11 bytes**. `native_width/height` are landscape pixels (iPad mini 6: 2266x1488). Max name_len 255.

**CONFIG** (host answers HELLO, and resends on any change; iPad must reset its decoder and wait for the next keyframe):
`codec u8 (1=H264) | reserved u8 (0) | width u16 | height u16 | fps u16 | bitrate_kbps u32` = **12 bytes**.

**VIDEO**: `pts_us u64 | flags u8 | reserved[3] (0)` = 12 bytes, then H.264 **Annex-B** access unit (4-byte start codes `00 00 00 01`, all slices of ONE frame in one message). flags: bit0 = keyframe (IDR), bit1 = contains SPS+PPS. Every keyframe MUST carry SPS+PPS inline before the IDR slice. No AUD required. `pts_us` is the host monotonic clock in microseconds.

**STATS** (iPad sends ~1/s): `frames_decoded u32 | frames_dropped u32 | last_decode_us u32` = 12 bytes.

### 2.3 Golden vectors (hex, full frame including header)
```
PING seq=1 ts=0x0102030405060708:
57 42 01 05 01 00 00 00 08 00 00 00 08 07 06 05 04 03 02 01
KEYFRAME_REQUEST seq=2:
57 42 01 04 02 00 00 00 00 00 00 00
CONFIG seq=3 codec=1 2266x1488 fps=60 bitrate=20000:
57 42 01 02 03 00 00 00 0C 00 00 00 01 00 DA 08 D0 05 3C 00 20 4E 00 00
```
`proto/vectors.json` (generated by the Rust crate, see T1) holds more, including HELLO and VIDEO. Both Rust and Swift tests MUST pass on every vector.

### 2.4 Session flow
1. Host finds the iPad via usbmuxd, connects to port 7878.
2. iPad sends HELLO. Host replies CONFIG (codec 1, host-chosen size/fps/bitrate), starts capture+encode, first frame is an IDR with SPS/PPS.
3. Steady state: VIDEO frames down; STATS/PING/KEYFRAME_REQUEST up.
4. iPad drop rule: if more than 2 frames are queued for decode, discard queued non-key frames and send KEYFRAME_REQUEST. Never buffer for smoothness.
5. Host drop rule: if the socket send would block (bounded channel full), drop the frame and force an IDR on the next encode. Never queue more than 1 encoded frame.
6. Disconnect (EOF/error/BYE): host stops encoding and goes back to waiting for a device. iPad goes back to listening.

## 3. Rust host (`host/`, cargo workspace, edition 2021)
Crates (each owns ONLY its directory):

### 3.1 `wb-proto` (no Windows deps, pure Rust)
```rust
pub const MAGIC: [u8;2] = *b"WB"; pub const VERSION: u8 = 1;
pub const HEADER_LEN: usize = 12; pub const MAX_PAYLOAD: u32 = 4*1024*1024;
pub struct Hello { pub proto_version:u8, pub codecs:u8, pub orientation:u8, pub native_width:u16, pub native_height:u16, pub max_fps:u16, pub name:String }
pub struct Config { pub codec:u8, pub width:u16, pub height:u16, pub fps:u16, pub bitrate_kbps:u32 }
pub struct Video { pub pts_us:u64, pub flags:u8, pub data:Vec<u8> }   // data = Annex-B
pub struct Stats { pub frames_decoded:u32, pub frames_dropped:u32, pub last_decode_us:u32 }
pub enum Message { Hello(Hello), Config(Config), Video(Video), KeyframeRequest, Ping(u64), Pong(u64), Orientation(u8), Stats(Stats), Bye, Unknown{ msg_type:u8, payload:Vec<u8> } }
pub fn encode(msg:&Message, seq:u32, out:&mut Vec<u8>);           // appends one full frame
pub struct FrameDecoder; impl FrameDecoder { pub fn new()->Self; pub fn push(&mut self, bytes:&[u8]); pub fn next(&mut self)->Result<Option<(u32 /*seq*/, Message)>, ProtoError>; }
pub enum ProtoError { BadMagic, BadVersion(u8), TooLarge(u32), BadPayload{msg_type:u8} }   // impl Display + Error
```
All structs derive `Debug, Clone, PartialEq`. `FrameDecoder` handles arbitrary chunking (byte-at-a-time must work).

### 3.2 `wb-usbmux`
usbmuxd plist protocol over TCP `127.0.0.1:27015`. Packet = 16-byte header (LE): `length u32 (incl. header) | version u32 (=1) | message type u32 (=8, plist) | tag u32`, then XML plist payload.
```rust
pub struct Device { pub id:u32, pub serial:String }
pub struct Usbmux { /* addr */ }
impl Usbmux { pub fn new()->Self /*127.0.0.1:27015*/; pub fn with_addr(addr:std::net::SocketAddr)->Self;
  pub fn list_devices(&self)->std::io::Result<Vec<Device>>;      // MessageType=ListDevices; keep only ConnectionType=="USB"
  pub fn connect(&self, device_id:u32, port:u16)->std::io::Result<std::net::TcpStream>; // MessageType=Connect, PortNumber = port.swap_bytes() as integer (network order). Result Number 0 => stream is now a raw tunnel; else io::Error
  pub fn wait_for_device(&self, poll_ms:u64, stop:&std::sync::atomic::AtomicBool)->std::io::Result<Option<Device>>; }
```
Requests carry `ClientVersionString`="workbuddy", `ProgName`="workbuddy", `kLibUSBMuxVersion`=3. Tested against an in-process mock usbmuxd (no hardware).

### 3.3 `wb-capture` (Windows only, `windows` crate)
```rust
pub struct OutputInfo { pub index:u32, pub adapter_name:String, pub device_name:String, pub width:u32, pub height:u32, pub attached:bool }
pub fn list_outputs() -> Result<Vec<OutputInfo>, CaptureError>;      // across all adapters; index = enumeration order, stable within a run
pub enum OutputSel { Primary, Index(u32), NameContains(String) }     // NameContains matches adapter_name or device_name, case-insensitive
pub struct Frame { pub texture: ID3D11Texture2D /*BGRA8, GPU, owned copy*/, pub width:u32, pub height:u32, pub pts_us:u64 }
pub struct Capturer;
impl Capturer { pub fn new(sel:OutputSel)->Result<Self,CaptureError>;
  pub fn device(&self)->&ID3D11Device;  pub fn size(&self)->(u32,u32);
  pub fn next_frame(&mut self, timeout_ms:u32)->Result<Option<Frame>,CaptureError>; }   // None on timeout / no new image. Handles DXGI_ERROR_ACCESS_LOST by recreating duplication internally.
```
Capturer creates the D3D11 device on the output's adapter (`D3D11_CREATE_DEVICE_BGRA_SUPPORT | VIDEO_SUPPORT`, multithread protection ON). Frame is a CopyResource into a private texture from a ring of 2, then ReleaseFrame immediately. `pts_us` = QueryPerformanceCounter-derived monotonic microseconds.

### 3.4 `wb-encode` (Windows only)
```rust
pub struct EncoderConfig { pub width:u32, pub height:u32, pub fps:u32, pub bitrate_kbps:u32 }
pub struct EncodedFrame { pub data:Vec<u8> /*Annex-B*/, pub keyframe:bool, pub has_params:bool, pub pts_us:u64 }
pub struct Encoder;
impl Encoder { pub fn new(device:&ID3D11Device, cfg:EncoderConfig)->Result<Self,EncodeError>;
  pub fn encode(&mut self, tex:&ID3D11Texture2D, pts_us:u64, force_idr:bool)->Result<Option<EncodedFrame>,EncodeError>;
  pub fn adapter_name(&self)->String; }
```
Input texture may be any size/BGRA8; internally a VideoProcessor converts+scales to NV12 `cfg.width x cfg.height`. Encoder is a hardware MFT (`MFT_ENUM_FLAG_HARDWARE`, category video encoder, H264). It is typically ASYNC: `MF_TRANSFORM_ASYNC_UNLOCK`, drive via `IMFMediaEventGenerator` (NeedInput / HaveOutput). Set: `CODECAPI_AVLowLatencyMode=true`, `CODECAPI_AVEncMPVDefaultBPictureCount=0`, `CODECAPI_AVEncCommonRateControlMode=CBR`, `CODECAPI_AVEncCommonMeanBitRate`, small VBV (`CODECAPI_AVEncCommonBufferSize` ~ bitrate/fps*1.5), `CODECAPI_AVEncMPVGOPSize` very large, `CODECAPI_AVEncCommonLowLatency=true`, `MF_LOW_LATENCY=true`. Attach the D3D11 device via `IMFDXGIDeviceManager` (`MFT_MESSAGE_SET_D3D_MANAGER`). Force IDR with `CODECAPI_AVEncVideoForceKeyFrame`. Output must be Annex-B; if the MFT emits SPS/PPS only via `MF_MT_MPEG_SEQUENCE_HEADER`, prepend them to every IDR. Call returns after at most ~50 ms (None = no output yet).

### 3.5 `wb-host` (binary, depends on all above)
CLI: `wb-host [--output <index|name>] [--fps 60] [--bitrate-kbps 20000] [--port 7878] [--list-outputs] [--dump <file.h264>]`.
`--dump` writes the Annex-B stream to a file instead of requiring a device (hardware-free validation; playable with ffplay). Threads: capture+encode thread; writer thread with a bounded(1) channel (drop rule 2.4.5); reader thread (KEYFRAME_REQUEST -> force_idr, PING -> PONG, STATS -> log). Logs per-second: fps, avg encode ms, kbps, dropped.

### 4.1 WBProto API (Swift, module `WBProto`)
```swift
public struct WBHello { public var protoVersion: UInt8; public var codecs: UInt8; public var orientation: UInt8; public var nativeWidth: UInt16; public var nativeHeight: UInt16; public var maxFps: UInt16; public var name: String; public init(...) }
```

All public structs/enums conform to `Equatable`. Little-endian read/write via explicit byte ops (no unaligned pointer loads).

### 4.2 VideoDecoder contract (`VideoDecoder.swift`, plain `import` of VideoToolbox/CoreMedia/CoreVideo/Foundation; does NOT import WBProto)
```swift
final class VideoDecoder {
  init()
  var onFrame: ((CMSampleBuffer) -> Void)?          // set by Session
  var onNeedKeyframe: (() -> Void)?                 // set by Session
  func reset()                                                         // drop session + parameter sets, wait for next keyframe
  func decode(annexB: Data, ptsUs: UInt64, keyframe: Bool)             // callable from the network queue; non-blocking-ish
  var framesDecoded: UInt32 { get }; var framesDropped: UInt32 { get }; var lastDecodeUs: UInt32 { get }
}
```
Behaviour: parse Annex-B NALs; on SPS(7)/PPS(8) (re)create the CMVideoFormatDescription (`CMVideoFormatDescriptionCreateFromH264ParameterSets`, NAL length 4) and VTDecompressionSession (`kVTDecodeFrame_EnableAsynchronousDecompression`, `RequireHardwareAcceleratedVideoDecoder`, output BGRA or NV12 IOSurface-backed); convert slices to AVCC (4-byte big-endian lengths), strip SPS/PPS/AUD from the sample; ignore non-key frames until the first keyframe after reset/start; decode with `_1xRealTimePlayback`; wrap the output CVPixelBuffer into a CMSampleBuffer with `kCMSampleAttachmentKey_DisplayImmediately = true` and call `onFrame`. If more than 2 decodes are in flight, drop incoming non-key frames, count them, call `onNeedKeyframe()` once. On decode error call `onNeedKeyframe()`.

### 4.3 DisplayView contract (`DisplayView.swift`)
```swift
final class DisplayRenderer { func enqueue(_ sb: CMSampleBuffer); func flush() }   // thread-safe; backs onto an AVSampleBufferDisplayLayer
struct DisplayView: UIViewRepresentable { let renderer: DisplayRenderer }          // black background, videoGravity .resizeAspect
```
`enqueue` drops the buffer if the layer is not ready (`isReadyForMoreMediaData == false`) after flushing stale content; if the layer status is `.failed`, call `flush()` first.

### 4.4 Session contract (`Net/Session.swift`, imports WBProto)
```swift
final class Session: ObservableObject {
  @Published private(set) var status: String      // "Waiting for PC on USB…", "Connected", etc.
  @Published private(set) var streaming: Bool
  init(decoder: VideoDecoder, renderer: DisplayRenderer)   // sets decoder.onFrame = renderer.enqueue, decoder.onNeedKeyframe = requestKeyframe
  func start(port: UInt16 = 7878); func stop()
  func requestKeyframe()
}
```
Uses Network.framework `NWListener` on the port; accepts ONE connection at a time (new connection replaces the old). On ready: send HELLO (proto 1, codecs 0x01, orientation 0, native size = `UIScreen.main.nativeBounds` as landscape (max,min), maxFps 60, name = `UIDevice.current.name`). Receive loop with `WBFrameDecoder`. CONFIG -> `decoder.reset()`, `renderer.flush()`, set streaming. VIDEO -> `decoder.decode`. PING -> PONG. Sends STATS every 1 s. `onNeedKeyframe` -> send KEYFRAME_REQUEST (rate-limited to 1 per 100 ms). On connection end: streaming=false, status back to waiting, listener stays up (recreate if it fails). `WorkBuddyApp` creates `VideoDecoder()`, `DisplayRenderer()`, then `Session(decoder:renderer:)`, and calls `session.start()` on appear.

## 5. Latency budget (stretch target 20 ms glass-to-glass, 60 Hz panel)
| Stage | Budget |
|---|---|
| Capture (DD wait + copy) | 1-2 ms (+ up to 16.7 ms frame-phase wait, avg 8) |
| Convert + encode (hw, no B-frames) | 3-5 ms |
| USB transfer | 2-3 ms |
| Decode (hw) | 2-4 ms |
| Display present (vsync, avg half frame) | ~8 ms |
Honest expectation for M1 at 60 Hz: 25-40 ms. 20 ms needs post-M1 work (direct NVENC slices, display-link-aligned capture). The per-second host log must expose encode ms so we can measure.
