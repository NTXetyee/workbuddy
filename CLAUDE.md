# WorkBuddy

iPad mini 6 as a USB second screen for a Windows 11 PC (RTX 5060 Laptop + Radeon 780M, MUX). Read `SPEC.md` for the architecture and wire protocol; `TASKS.md` for status.

## Roles
- Lead architect (Claude Sonnet) writes only SPEC.md, TASKS.md, CLAUDE.md and worker briefs. Implementation is done by Haiku worker agents, one task each, with disjoint file ownership (SPEC section 6).
- Workers: touch only the files named in their brief; no drive-by edits; run the validation command before returning; report exact output.

## Repo layout
```

```

## Build / test
Host (from `host/`):
```
cargo test -p wb-proto
cargo test -p wb-usbmux
cargo test -p wb-capture        # needs a GPU session, runs on this PC
cargo test -p wb-encode
cargo build --release -p wb-host
cargo run --release -p wb-host -- --list-outputs
cargo run --release -p wb-host -- --output 0 --dump out.h264     # no iPad needed
```
Workers building in parallel should pass `--target-dir target-<crate>` to avoid lock contention.
Lint: `cargo fmt --check` and `cargo clippy -p <crate> -- -D warnings` (warnings allowed in windows-sys glue via targeted `#[allow]`).

iPad (cannot build locally; no Mac): the only validation is CI.

## CI loop (iPad)
1. Commit batched iOS changes, `git push origin <branch>`.
2. `gh run watch --exit-status` (or `gh run list --limit 1` then `gh run view <id> --log-failed`).
3. Route the exact compiler errors to the worker who owns the file. Repeat until green.
4. Download IPA: `gh run download <id> -n WorkBuddy-ipa -D dist/`.
Batch iOS edits so each push tests as much as possible.

## AltStore install (user)
1. PC: iTunes/Apple Devices installed, AltServer running in the tray, iPad connected by USB, trusted.
2. Download `WorkBuddy.ipa` from the Actions artifact (zip, extract it).
3. Tray AltServer icon -> Sideload .ipa... -> pick the iPad -> sign in with Apple ID.
4. iPad: Settings -> General -> VPN & Device Management -> trust the Apple ID profile. Free accounts must refresh every 7 days.
5. Launch WorkBuddy on the iPad (keep it foreground), then start `wb-host` on the PC.

## Latency budget (stretch 20 ms glass-to-glass; honest M1 expectation 25-40 ms)
capture 1-2 ms (+ frame-phase wait), convert+encode 3-5 ms, USB 2-3 ms, decode 2-4 ms, present ~8 ms avg. Latency beats quality: drop frames, never buffer. Details in SPEC section 5.

## Conventions
- Wire format is little-endian, defined in SPEC section 2; Rust and Swift must both pass `proto/vectors.json`.
- Host crates have no cross-crate behavior beyond the SPEC contracts.
- iOS: `SWIFT_VERSION 5.0`, no third-party packages, no storyboard, no hand-edited .xcodeproj (generated, gitignored).
- Commits are made by the architect only, not by workers.

## Daily use (as built)
- Desktop shortcut **WorkBuddy** (made by scripts/make-shortcut.ps1) -> conhost.exe -> scripts/start-wb-host.ps1 -> finds the 2266x1488 output, runs host\target-all\release\wb-host.exe in a classic console. Minimize = hide to tray (tooltip shows status); tray menu: Show window / Quit. Closing the window stops the host. Flags: --verbose (per-second diagnostics), --no-tray, --idle-fps N, --output N.
- Rebuild: stop the host first (it locks the exe), then cargo build --release -p wb-host --target-dir target-all from host/.
- Encoder: direct NVENC when available (1.7-2.6 ms), MFT fallback; WB_ENCODER=mft|nvenc forces one. No GPU clock lock needed.
- iPad: re-sideload from the CI artifact (WorkBuddy-ipa) on each iOS change; AltStore refresh every 7 days.
- Not built: touch/Pencil, rotation, latency counter (est. 30-40 ms glass-to-glass, unmeasured).
